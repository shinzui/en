# Capability

- [Batch check many subject/permission/object triples in one call](batch-check.md) - Submit many check pairs in one request and get one decision per pair, in order, so a GraphQL field-capability map or a candidate-filtering pass costs one round trip instead of N.
- [Biscuit decision tokens: mint, verify, attenuate](biscuit-decision-tokens.md) - Turn a successful en decision into a short-lived signed Biscuit a downstream service can verify locally and attenuate before forwarding, with key ids, keyset rotation, and block-based revocation.
- [Bulk import and export of relationships](bulk-import-export.md) - Stream every live relationship to stdout as JSON lines, and read them back in bounded transactions, as en-server subcommands for seeding, migration, and backup.
- [Check a permission, with caveats and obligations](check-decisions-with-caveats.md) - Answer check(subject, permission, object) as Allowed, Denied, or Conditional with the caveat obligations still outstanding, evaluated over the compiled reachability graph at a named consistency.
- [Compile-time schema validation](compile-time-schema-validation.md) - Validate a schema during compilation with a Template Haskell splice or a quasi-quoter, so an invalid model fails the build with the same error the runtime validator would return.
- [Consistency tokens and snapshot reads](consistency-tokens-and-snapshot-reads.md) - Pin a read to a PostgreSQL snapshot with an en1. consistency token that encodes datastore identity, schema hash, and revision, and choose per request between minimum latency, at-least-this-snapshot, and fully consistent.
- [Operator-configurable evaluation budget](evaluation-budget.md) - One record bounding recursion depth, storage read batch size, and returned result size for check, lookup, and expand, configurable by the operator rather than hard-coded per engine.
- [Expand a permission into its subject tree](expand-subject-tree.md) - Return the tree of relations and usersets that grant a permission on an object, so a reviewer can see why access holds rather than only that it holds.
- [Typed Haskell client for the standalone service](haskell-client.md) - A servant-client-backed Haskell client mirroring the whole /v1 surface, with a helper for chaining a read against the consistency token a previous call returned.
- [In-process decision and tuple-read caching](in-process-caching.md) - Bounded in-process caches for authorization decisions, evaluation subproblems, and tuple reads, wired in as a store decorator, with hit/miss statistics exposed for metrics.
- [Lookup the objects a subject can reach](lookup-objects.md) - Answer lookup(subject, permission, objectType) as a paged, cursor-resumable list of objects the subject may reach, with a per-request deadline and an explicit exhausted/limited outcome.
- [Lookup the subjects that can reach an object](lookup-subjects.md) - Answer the reverse question — which subjects hold a permission on a given object — as a paged, cursor-resumable list, for share sheets, audits, and notification fan-out.
- [PostgreSQL schema as an append-only pg-migrate component](postgres-migrations.md) - en's database schema as a pg-migrate migration component whose SQL is embedded at compile time from an ordered manifest, applied by an en-migrate CLI with per-file checksums, advisory-lock safety, and machine-readable exit codes.
- [PostgreSQL tuple store](postgres-tuple-store.md) - A hasql-backed implementation of the tuple store and consistency store effects, with xid8 soft-delete, filtered and paged reads, and a connection-pooled session runner.
- [Reachability compilation and schema hashing](reachability-compilation.md) - Compile a validated schema into a reachability graph that indexes which subject shapes can reach which relations, and carries an insertion-order-independent schema hash.
- [Write and delete relationship tuples, with preconditions](relationship-writes.md) - Write, touch, and delete relationship tuples — individually, in batches, by filter, or as an atomic mixed write guarded by must-exist / must-not-exist preconditions — and get back the consistency token for the write.
- [Fail-closed authorization guard for host routes](require-permission-guard.md) - requirePermission wraps a check for a Servant handler so that denied, conditional, and engine-error outcomes all refuse the request, with a worked resolver pattern for GraphQL hosts.
- [Render a schema as docs and diagrams](schema-docs-and-diagrams.md) - Render a schema to Markdown reference text, a Mermaid schema diagram, or a Mermaid reachability diagram, with byte-stable output suitable for checking into a repository.
- [Schema-parametric authorization model](schema-parametric-model.md) - Supply your own object types, relations, permissions, usersets, and caveats as a Haskell value built with a checked builder DSL, and get a validated schema the engine is generic over.
- [Reload and preflight a schema without restarting](schema-reload-and-preflight.md) - Signal a running server to re-read its schema file and swap the active model atomically, refusing any candidate that would orphan stored tuples, and preflight the same check offline with a check-schema subcommand.
- [Servant HTTP API with a generated OpenAPI document](servant-http-api.md) - The whole read and write surface as a typed Servant API under /v1, with wire types, a structured error envelope, and an OpenAPI 3 document generated from the same types and checked against them.
- [Standalone authorization server](standalone-authorization-server.md) - A deployable HTTP service over the libraries with startup-validated configuration, API-key auth, rate limiting, optional TLS, health and readiness probes, Prometheus metrics, JSON request logging, graceful shutdown, and background GC.
- [Text schema language](text-schema-language.md) - Parse en's line-oriented text schema language into a Schema, so a server or an application can load its authorization model from a file at runtime instead of compiling it in.
- [Report stored tuples that no longer match the schema](tuple-schema-drift-report.md) - Scan a store against a candidate schema and report every orphaned tuple with the reason it no longer fits, as the preflight a schema change needs before it is activated.
- [Poll a windowed watch feed of tuple changes](watch-feed.md) - Subscribe to relationship changes from now, from a cursor, or from an ordinary consistency token, and drain each revision window across polls with a cursor that pins both window edges.
